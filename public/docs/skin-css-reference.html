Skin CSS reference

What each variable and class actually touches, so you're not guessing while writing a skin's Custom CSS. Numbers on the mockup match the numbered cards below.

Two tiers of variables. The first tier — palette, fonts, opacity, background, custom assets — is set automatically from the editor's form fields; you never declare these yourself. The second tier — --skin-paper-line, --skin-entry-date-* — has a sensible default but is only meant to be overridden by a skin's own Custom CSS, in a :root { ... } block, the way the paper-recipe skins already do.

Reference

1Page background

The base colour and optional tiled/centered/cover image behind everything, on body.

--skin-bg --skin-bg-image --skin-bg-repeat --skin-bg-position --skin-bg-size
2Bottom nav

Today / Calendar / Stats / Packs / More. Translucency comes from the chrome opacity slider; active-tab colour is the accent.

--skin-chrome-opacity --skin-accent .bottom-nav .bottom-nav__link .bottom-nav__link--active
3Date header

The date text and its two arrow buttons. Font size/weight/family for the date itself are skin-definable, not set by the editor.

--skin-entry-date-size --skin-entry-date-weight --skin-entry-date-family --skin-fg .entry-date-nav .entry-date-nav__arrow .entry-date-nav__date
4Pack tabs

Only rendered when 2+ content packs are active — with one pack, this whole row doesn't exist in the DOM.

--skin-accent --skin-bg --skin-fg .pack-tabs .pack-tabs__tab .pack-tabs__tab--active
Watch out: base CSS gives .pack-tabs its own margin-top: 0.65rem, separate from any gap on its parent. Easy to miss if you're trying to control vertical rhythm precisely.
5Free write / pack panels

The card-like containers for free write and each pack. Surface opacity controls how see-through they are over the page background. Free write renders after pack prompts when enabled.

--skin-surface-opacity --skin-bg --skin-muted .free-write .pack-section .pack-section__section [data-panel-style]
[data-panel-style] is set on <html> from the Surface style dropdown — flat / card / sticky / paper all have real recipes now, keyed off this attribute, e.g. [data-panel-style="paper"] .pack-section { ... }.
6Section headers / toggles

The clickable title bar for a pack or a nested section within it (the chevron, the title text).

--skin-accent --skin-font-display .pack-section__header .pack-section__toggle .pack-section__title .pack-section__chevron .pack-section__section-header .pack-section__section-toggle .pack-section__section-title
7Field label

A prompt's label row — includes an optional required-mark and an optional shuffle-prompt button.

--skin-fg --skin-accent .field .field-label-row .field-label .field-label__required .field-redraw
8Short answers

Single-line text / date / number inputs.

--skin-field-bg --skin-field-fg --skin-field-border --skin-field-opacity .field-input .field-input--short .field-input--date
9Long answers

Free write and pack-section textareas. Same field vars as short answers, plus the ruled-line unit if a paper-style skin uses it.

--skin-field-bg --skin-field-fg --skin-field-border --skin-paper-line .field-input--textarea .field-input--free-write
Both carry an HTML rows= attribute — a CSS min-height alone won't override that if the browser's own row calculation comes out taller; use height if you need an exact size.
10Yes / No buttons

Paired Yes / No controls for yesNo fields. Active state uses the accent colour.

--skin-accent --skin-bg .yes-no-buttons .yes-no-btn .yes-no-btn--active
11Checklist

Fixed option list for checklist fields. Checkbox accent colour follows --skin-accent.

--skin-accent .checklist .checklist__item .checklist__label .checklist__input
12Save button + status

Manual save control plus autosave status and hint text under the entry form.

--skin-accent --skin-bg --skin-muted .entry-actions .entry-save-button .entry-save-state .entry-save-hint
—Custom assets (not shown)

Every image you add in a skin's Custom assets list becomes its own variable, usable anywhere in that skin's Custom CSS — not fixed like the others above.

--skin-asset-<your-key>
